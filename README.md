# Анализатор метрик Холстеда для JavaScript

Программа-парсер с графическим интерфейсом (Tkinter). Анализирует исходный
код на JavaScript и рассчитывает **6 базовых** и **3 расширенных (производных)**
метрики Холстеда — по аналогии с примером 1 из методички
"Метрики размера программ" (пример на Паскале), адаптированным под JS.

## Файлы

- `halstead_core.py` — токенизатор JavaScript и логика расчёта метрик
  (можно использовать отдельно, без GUI).
- `halstead_gui.py` — графический интерфейс (Tkinter). **Это главный
  запускаемый файл.**
- `example.js` — пример кода для проверки работы программы.

## Запуск

Нужен только стандартный Python 3 (модуль `tkinter` входит в стандартную
поставку на Windows/macOS; на Linux иногда требуется
`sudo apt install python3-tk`). Внешние библиотеки не нужны.

```bash
python3 halstead_gui.py
```

В окне программы:
1. Вставьте код в левое текстовое поле или откройте `.js`-файл кнопкой
   «Открыть файл...» (уже подставлен встроенный пример).
2. Нажмите «Рассчитать метрики».
3. Справа появятся:
   - таблица **Операторы** (столбцы j / Оператор / f1j),
   - таблица **Операнды** (столбцы i / Операнд / f2i),
   - строка с базовыми метриками η1, N1, η2, N2,
   - блок **Расширенные (производные) метрики**: словарь программы η,
     длина программы N, объём программы V.

## 6 базовых метрик Холстеда

| Метрика | Значение |
|---|---|
| η1 | число уникальных операторов |
| η2 | число уникальных операндов |
| N1 | общее число операторов |
| N2 | общее число операндов |
| f1j | число вхождений j-го оператора (столбец в таблице) |
| f2i | число вхождений i-го операнда (столбец в таблице) |

## 3 расширенные (производные) метрики

- **Словарь программы**: η = η1 + η2
- **Длина программы**: N = N1 + N2
- **Объём программы**: V = N · log₂(η)

## Правила классификации операторов/операндов (адаптация Пascal → JavaScript)

**Операторы:**
- ключевые слова: `var let const function return if else for while do
  switch case default break continue try catch finally throw new delete
  typeof instanceof in of class extends super import export from async
  await yield void with debugger static get set`;
- знаки операций и присваивания: `+ - * / % ** = += -= *= /= %= **= == !=
  === !== < > <= >= && || ?? ! & | ^ ~ << >> >>> ++ -- ? : => ...`;
- пунктуация: `,` `;` `.`;
- фигурные скобки `{ }` — считаются **одним** оператором на пару
  (аналог `Begin...End` в Пascal);
- квадратные скобки `[ ]` — считаются одним оператором на пару
  (индексация / литерал массива);
- **круглые скобки `( )`** — считаются одним оператором на пару **только
  если используются для группировки выражения** (математика/логика,
  приоритет операций), например: `(2 + 3) * (4 - 1)`.
  Если скобки — часть управляющей конструкции (`if(...)`, `while(...)`,
  `for(...)`, `switch(...)`, `catch(...)`), список параметров
  `function(...)` или вызов функции `foo(...)` — такие скобки
  **самостоятельным оператором не считаются** (согласно заданию).

**Операнды:**
- идентификаторы (имена переменных, функций, свойств);
- числовые литералы (целые, дробные, экспоненциальные, hex/bin/oct);
- строковые и шаблонные литералы (`'...'`, `"..."`, `` `...` ``);
- регулярные выражения `/.../flags`;
- литералы `true`, `false`, `null`, `undefined`, `NaN`, `Infinity`, `this`.

## Пример проверки правила скобок

```js
if (n <= 1) {        // скобки после if — НЕ оператор
    return foo(n - 1); // скобки вызова функции — НЕ оператор
}
let x = (a + b) * (c - d); // обе пары скобок — оператор "()" (группировка)
```

## Известные ограничения (упрощения парсера)

- Регулярные выражения распознаются эвристически (по контексту
  предыдущего токена) — в редких неоднозначных случаях возможна ошибка
  трактовки `/` как деления или наоборот.
- Внутри строковых `` `шаблонов` `` содержимое `${...}` не разбирается
  отдельно — весь шаблон считается одним операндом-строкой.
- Метки (labels) для `break`/`continue` в подсчёте не выделяются отдельно.

Эти допущения не влияют на демонстрацию базового принципа расчёта метрик
Холстеда и правило подсчёта скобок, указанное в задании.
